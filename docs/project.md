# Ariadne Forge 프로젝트 헌장

## 목적

Ariadne Forge는 Codex가 개발 작업을 수행할 때 중요한 판단을 근거와 연결하고, 작은 오판이 검토 없이 연쇄적으로 확정되는 것을 줄이는 저장소 전용 작업 방식이다.

목표는 LLM의 추론을 없애는 것이 아니다. 요구 해석, 문제 분해, 설계 후보와 구현에는 추론이 필요하다. 대신 다음을 명시적으로 만든다.

- 어떤 근거와 프로젝트 문서를 읽었는가
- 어떤 선택지와 반례를 검토했는가
- 누가 제안·작성·검증했는가
- 무엇이 실제 실행 결과로 확인됐는가
- 어떤 불확실성과 결정이 남았는가

## 최우선 품질 목표

1. **근거 추적성**: 중요한 결정은 요구사항, 프로젝트 규범, 저장소 사실, 실행 결과 또는 직접 확인한 외부 자료와 연결된다.
2. **오류 격리**: 작성자의 주장만으로 승인·완료하지 않고, material finding은 독립 시각과 직접 증거로 다시 본다.
3. **유연성**: 연구 필요성과 다음 행동을 닫힌 그래프로 모두 선모델링하지 않는다. 어느 단계에서도 새 불확실성이 생기면 연구·재계획·사용자 결정으로 돌아갈 수 있다.
4. **낮은 유지보수 비용**: 현재 실패를 줄이는 가장 작은 Skill·문서·검사만 추가한다.
5. **에이전트 가독성**: 저장소 안에서 현재 규칙과 결정 이유를 찾을 수 있고, 거대한 단일 지침에 의존하지 않는다.

## 비목표

- 모든 LLM 판단을 결정론적 코드로 대체하기
- 범용 workflow engine, 프로젝트 관리 UI 또는 분산 worker를 먼저 만들기
- 모든 작업에 다중 에이전트·리서치·비판을 강제하기
- JSON, graph, 데이터베이스 또는 vector store를 제품 정체성으로 삼기
- 현재 Skill-first 구현에 Codex SDK, Codex App Server, OpenAI Agents SDK, LangGraph 또는 runtime observer·graph·state runtime 코드와 dependency를 넣기
- MengTo/Skills나 다른 외부 Skill의 결론을 프로젝트 디자인 권위로 취급하기
- 폐기 예정인 Harness Maestro를 계승하거나 호환 계층을 만드는 것

## 성공의 의미

초기 성공은 “완벽한 오케스트레이터”가 아니라 다음 변화로 측정한다.

- 관련 문서 누락, 근거 없는 중요 선택, 거짓 완료가 baseline보다 줄어든다.
- Quick 작업의 불필요한 절차 비용은 허용 한도 안에 남는다.
- Standard/Deep 작업에서 연구·비판·검증이 실제 결정 변경에 기여한다.
- Skill과 문서를 수정할 이유가 실패 사례와 평가 결과로 설명된다.
- 코드 런타임 없이도 유효하면 그 상태를 유지한다.

## 중단 원칙

조사나 pilot에서 핵심 가정이 틀리면 기존 계획을 방어하지 않는다. 그 경로를 `STOP`으로 기록하고, 이미 얻은 증거를 보존한 뒤 더 작은 대안이나 다른 표면으로 돌아간다. 반대로 비판 자체도 자동으로 참이 아니며, 더 강한 근거가 있으면 타당하게 반박할 수 있다.
